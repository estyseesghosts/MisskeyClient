## 4. Geometry

### Shared Rules

Use a small set of presentation tokens, not a new design framework. Keep component-specific measurement close to its component.

- Use true capsule shapes for action pills and tab chips.
- Give interactive controls at least 48 dp in both touch dimensions.
- Let text controls grow vertically for larger fonts and translated text.
- Keep equal inset distances around nested surfaces that follow the same curve.
- Derive related radii from one outer radius and one inset.
- Use the relationship `innerRadius = max(0, outerRadius - inset)` for matching nested rounded corners.
- Do not apply that formula to unrelated edges or shapes with different centers.
- Use equal gaps within each repeated row and between equivalent rows.
- Keep visible bounds, clipping, ripple bounds, and touch bounds intentional.
- Keep surface sizing stable when an icon becomes selected.
- Animate icon emphasis without shifting the outer pill or changing its end curves.

### Navigation Measurements

Start with these candidate dimensions. Confirm them at real device scale before accepting them.

| Measurement | Candidate | Relationship |
|---|---|---|
| Contained bubble diameter `D` | 48 dp | Same diameter for all four navigation controls. |
| Outer inset `I` | 4 dp | Equal at the left, right, top, and bottom. |
| Internal gap `G` | 4 dp | Same gap between each contained bubble. |
| Outer pill height | `D + 2I = 56 dp` | Outer radius equals half this height. |
| Outer pill width | `4D + 3G + 2I = 212 dp` | No weight-based stretching. |
| Contextual diameter | 56 dp | Vertically aligned with the outer pill. |
| Contextual gap | 8 dp | Separate from the four-item pill. |
| Full assembly width | 276 dp | Fits a 320 dp window with 16 dp side margins. |

The end bubbles have a 24 dp radius. The outer pill has a 28 dp radius. A 4 dp inset gives shared curve centers.

Draw a quiet bubble surface for each inactive destination. Give the selected destination a stronger theme treatment.

Retain the profile avatar, but place it inside the same bubble geometry. The selected background must remain visible around it.

When the contextual action is absent, keep the four-item pill compact. Do not stretch it to occupy the missing action space.

For unusually narrow windows, reduce empty gaps before reducing required touch targets. Never hide a destination to make the assembly fit.

### Card Measurements

- Start with an 8 dp outer inset and an 8 dp repeated control gap.
- Use equal row weights for the two account actions and the two moderation columns.
- Keep both controls in a row the same height after text measurement.
- Choose the card radius from the visible edge controls and their inset.
- Treat the share group as a second nested level with its own derived inner radius.
- Keep the three share targets equally spaced inside that group.
- Use one compact width policy for normal and problem states.
- Bound width by the available window or pane, not only `LocalConfiguration.screenWidthDp`.
- Replace the fixed two-thirds-width rule where it prevents readable half-width actions.
- Keep a preferred compact maximum near the existing 360 dp limit, subject to device review.
- Allow a wider card within safe margins when large text requires it.

Prefer matching normal and problem heights when their content fits. Allow necessary growth for report entry, errors, and large text.

Do not lock the card to a small fixed height. Do not create a full-width generic bottom sheet.

### Colors

Use the existing `MaterialTheme.colorScheme` roles and their intended foreground pairs.

| Element | Initial theme treatment |
|---|---|
| Outer action and hashtag containers | `surfaceContainerHigh` with `onSurface`. |
| Action bubbles and share group | Container roles with their corresponding foreground roles. |
| Selected navigation and Home tabs | An accented container with its corresponding foreground role. |
| Contextual navigation action | `primaryContainer` with `onPrimaryContainer`. |
| Inactive navigation | A quieter surface role with `onSurfaceVariant`. |
| Errors | Existing error roles. |
| Disabled controls | Existing theme-derived disabled treatment with distinct semantics. |

Use the same selected treatment across equivalent controls. Do not copy the mockup's yellow, brown, white, or black values.

Theme roles may resolve to white or black. Do not add tests that reject those resolved colors.

Check contrast on the actual background, including translucent navigation over posts. Increase container opacity if content behind the control harms readability.

Preserve System Monochrome, dynamic colors, palette selection, and background overrides. This task does not change those preferences.
