# Default Unicode Emoji Extraction

## 1. Current data ownership

`EmojiPicker.kt` currently declares `DefaultUnicodeEmojis` at lines 91-126.

- The declaration uses the `me.foxtails.palustris.ui.emoji` package.
- The symbol has `internal` visibility.
- The value uses `listOf`, so callers receive a read-only `List<String>` API.
- The top-level value creates the list once during file initialization.
- The list contains repeated values, including `😢`, `🤔`, `👀`, `🙏`, and `🔥`.

The symbol became `internal` when grouping moved to `EmojiPickerGrouping.kt`. A second source file now needs the value. The current checkout has no strong structural reason to reject `DefaultUnicodeEmoji.kt`.

## 2. Current consumers

The repository has three references to `DefaultUnicodeEmojis`.

- `EmojiPicker.kt:91` declares the list.
- `EmojiPicker.kt:371-372` maps each value to an `EmojiChoice` for the picker grid.
- `EmojiPickerGrouping.kt:40` maps each value to an `EmojiChoice` for the standard group.

`EmojiPicker.kt:390-405` uses the mapped choices for the compact picker. It keeps recent choices, takes the first eight Unicode choices, and removes duplicate submission values.

`EmojiPickerGrouping.kt:46` combines Unicode choices with additional standard choices. `distinctBy` keeps the first occurrence. The standard group therefore preserves the list order and the first occurrence of each repeated value.

`EmojiPickerGrouping.kt:74-78` searches Unicode choices through their submission value and display text. The list contents therefore affect search results.

No test references `DefaultUnicodeEmojis` directly. Existing tests exercise the data indirectly:

- `app/src/test/java/me/foxtails/palustris/ui/EmojiPickerTest.kt:120-127` checks that the picker shows default and server choices.
- `app/src/test/java/me/foxtails/palustris/ui/EmojiPickerTest.kt:258-290` checks group order and Unicode group placement.
- `app/src/test/java/me/foxtails/palustris/ui/EmojiPickerTest.kt:222-255` checks compact and expanded grid behavior with `👍`.
- `app/src/test/java/me/foxtails/palustris/HomeFeedTest.kt:802-828` checks compact reaction selection with `👍`.
- `app/src/test/java/me/foxtails/palustris/SignInScreenTest.kt:265-270` checks reaction selection with `🎉`.

## 3. Proposed extraction

Create `app/src/main/java/me/foxtails/palustris/ui/emoji/DefaultUnicodeEmoji.kt`.

- Copy the package declaration from `EmojiPicker.kt`.
- Move the `DefaultUnicodeEmojis` declaration without changing one list entry.
- Keep the existing symbol name.
- Keep `internal` visibility because both `EmojiPicker.kt` and `EmojiPickerGrouping.kt` need the value.
- Keep the top-level `val` and `listOf` construction.
- Remove only the declaration from `EmojiPicker.kt`.

The two consumers remain in the same package. They need no import and no API change. Do not create an object or a new wrapper for this one static data set.

## 4. Behavior that must stay unchanged

- Preserve every list entry, including repeated values and variation selectors.
- Preserve the exact list order.
- Preserve the first eight Unicode choices used by the compact picker.
- Preserve the standard group position after recent, post-specific, and server groups.
- Preserve search matching and result order.
- Preserve `distinctBy` behavior for repeated Unicode values and additional choices.
- Preserve the `EmojiChoice` submission value and display text for every Unicode entry.
- Preserve selected-state matching through each choice submission value.
- Preserve one-time list initialization and the read-only collection API.

The repeated values do not create repeated visible cells because both picker paths remove duplicate submission values. They still remain part of the source data contract. The first occurrence can affect the resulting order, so the extraction must not deduplicate the source list.

## 5. Refactor order

1. Add `DefaultUnicodeEmoji.kt` in the existing `ui.emoji` package.
2. Move the declaration byte-for-byte from `EmojiPicker.kt`.
3. Remove only the old declaration block from `EmojiPicker.kt`.
4. Leave `EmojiPickerGrouping.kt`, picker limits, search logic, and UI code unchanged.
5. Add a focused test for the ordered default list if the project accepts the test addition in this slice.

## 6. Verification

Use a focused test to compare `DefaultUnicodeEmojis` with an ordered expected snapshot. Include repeated entries in that snapshot. This test makes accidental reordering, removal, addition, normalization, or deduplication visible.

Keep the existing UI tests as behavior checks. In particular, run the picker, Home feed, and sign-in tests that select `👍` and `🎉`.

Check the source diff to confirm that only the file location changed. Check that the declaration has one definition and the two existing consumers remain unchanged.

Run the required Windows Gradle checks after implementation:

- `gradlew.bat test`
- `gradlew.bat assembleRelease`

Compose tests confirm picker behavior in the test environment. They do not confirm glyph rendering with every Android system font.

## 7. Risks and open questions

- No current test protects the complete default list. A middle-of-list change could pass the existing UI tests.
- The list contains duplicates. Their visible effect is removed later, but their source order must remain unchanged.
- The list is internal. No current test or production caller requires a public API.
- Moving the value can change behavior if a new file uses a mutable collection, a function that rebuilds the list, or a sorted collection. The proposal avoids all three changes.
- Android font coverage can change how some Unicode sequences render. That risk exists before and after this ownership change and remains outside this refactor.
